# 2025–2026 GPU 深度学习调度论文补充设计

## 目标

延续仓库现有 README 的组织方式，为 2025–2026 年补充 GPU 数据中心中的深度学习训练与推理调度论文，重点覆盖 CCF-A 会议，并保持论文条目的可核验性。

## 纳入标准

- 仅将已正式发表、已进入官方 proceedings，或已由会议官方明确录用且可核验的论文放入主表。
- 2026 年以 2026-08-17 为信息截止日；只有在截止日前能找到官方论文集、会议录或出版社页面的论文才纳入。
- 优先覆盖与 GPU 数据中心、深度学习训练/推理 workload 调度直接相关的 CCF-A 会议论文。
- 非 CCF-A 论文只在与主题高度相关且出版信息明确时少量补充。
- 仅有 arXiv 预印本、Workshop 或工业报告的工作不放入主表，除非后续已获得符合上述条件的正式出版信息。

## README 变更

- 继续使用 `Schedulers for DL Training` 与 `Schedulers for DL Inference` 两张表。
- 沿用现有字段：调度器名称、年份、会议、论文链接、目标指标、异构性、弹性、AutoML 和代码信息。
- 新条目按年份从新到旧插入对应表格顶部。
- 对没有公开代码的论文保留 `-`，不根据项目主页或作者仓库的非正式状态推断代码可用性。
- 在 README 的相关位置注明本次整理的截止日期和纳入原则，避免读者将候选预印本与正式论文混淆。
- 不修改既有条目的分类，除非核验过程中发现链接或会议年份存在明确错误。

## 核验流程

1. 从 2025–2026 年 CCF-A 会议论文集和官方会议页面建立候选集。
2. 使用论文官网、出版社页面或正式 proceedings 交叉核对标题、年份、会议和 DOI/稳定链接。
3. 阅读摘要及方法描述，判断论文属于训练调度、推理调度，还是不属于本仓库主题。
4. 根据论文明确描述填写 Objective、Heter.、Elastic、AutoML 等字段；没有证据的字段保持 `-`。
5. 检查代码链接是否为论文作者或项目官方仓库。
6. 对 README 做格式检查，确认 Markdown 表格、锚点和链接完整。

## 验收标准

- 每个新增条目都具备可访问且与该论文对应的正式论文链接。
- 每个新增条目都能说明其训练/推理归属及调度目标。
- CCF-A 条目优先级清晰，会议名称和年份与官方来源一致。
- README 不包含仅凭 arXiv 标注为正式会议论文的条目。
- 变更只涉及论文列表、纳入说明及本设计文档，不引入无关代码或结构性重构。
